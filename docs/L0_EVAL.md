# L0-eval — точность классификатора шоков (Agent 1)

> **Что это.** Живой прогон L0-классификатора (Agent 1) на gold-set из **50
> диверсифицированных** синтетических **публичных** новостей. Проверяем, правильно ли
> агент раскладывает новость по таксономии шоков (5 категорий / 27 подкатегорий) —
> прежде чем результат уйдёт в L1–L3.

> **Что это НЕ.** Не статистически значимый бенчмарк. N=50 — расширенный **sanity-check**,
> а не leaderboard. Метки проставлены вручную по таксономии; новости синтетические
> (клиентских/портфельных данных банка нет — [принцип изоляции](../CLAUDE.md)).

Сводная витрина всех метрик проекта — [EVAL.md](EVAL.md) (`python eval_all.py`).

Источник чисел — [`_tools/data/l0_eval_results.json`](../_tools/data/l0_eval_results.json)
(собран из сырых прогонов `output/l0_eval/`, которые в `.gitignore`).
Gold-set — [`_tools/data/l0_gold_set_50.json`](../_tools/data/l0_gold_set_50.json)
(схема/покрытие проверяются `tests/test_l0_gold_set.py`, CI-safe).

---

## Gold-set (N=50)

- **Все 27 подкатегорий** покрыты (1–3 примера на подкатегорию).
- **Диверсификация:** разные источники (ТАСС/Reuters/Bloomberg/Минфин/ЦБ/Росстат/…),
  формулировки, длины, именованные сущности.
- **8 boundary-кейсов** (`boundary=true`) — намеренно пограничные: снижение/повышение
  ставки «ровно по консенсусу, уже в ценах» (5.2 vs 4.x); угроза/ультиматум без действия
  (5.3 vs 1.x); календарный/сезонный артефакт (5.4 vs 2.6/4.6).

## Метод

- **Промпт — продакшн, не отдельный.** Harness (`_tools/eval_l0_classifier.py`) берёт
  ровно тот промпт, что уходит в прод: `orchestrator.extract_prompt(agent_1_classifier.md)`.
- **Таксономия инлайнится** (в проде `--llm-mode cli` читает её файлом; голый API — нет).
- **Метрики:** accuracy по `main_category` (5 классов) и `subcategory` (27 классов);
  boundary считаются отдельной колонкой. **Стоимость** — из `response.usage` × тарифы.
- **thinking-модели:** `response_text()` берёт именно text-блок (у Sonnet-5 `content[0]`
  это ThinkingBlock без `.text`) — иначе прогон падал бы.

## Результаты

**Haiku 4.5 на полном N=50** (прогон 2026-07-23):

| Метрика | Значение | 95% Wilson CI |
|---|:-:|:-:|
| main-category (5-класс.) | **94% (47/50)** | [0.84, 0.98] |
| subcategory (27-класс.) | **96% (48/50)** | [0.87, 0.99] |
| subcat без boundary | 95.2% (40/42) | — |
| boundary | 8/8 | — |

Стоимость Haiku-прогона: **$0.18**. CI на N=50 заметно уже, чем на сокращённом наборе
N=15, но это всё равно sanity-check, не бенчмарк.

**Разбор промахов.** Подкатегорию модель ошибает на 2 из 50 (оба — спорная граница), плюс
один main-промах при верной подкатегории:

| id | gold | pred | тип | разбор |
|---|---|---|---|---|
| **n06** | 1.3 | 2.4 | main+sub | Подрыв магистрального газопровода: Haiku — операционный сбой инфраструктуры (2.4), эталон — геополитический удар по инфраструктуре (1.3). Граница диверсия↔авария объективно неоднозначна. |
| **n29** | 3.5 | 2.4 | main+sub | Пожар на НПЗ, «остановил установку, поставки под вопросом» — это и техногенная ЧС (3.5), и инфраструктурный сбой (2.4). Метка 3.5 **контестабельна**, а не чистая ошибка; оставлена как есть (не подгоняем разметку под модель), промах засчитан честно. |
| **n43** | 5.2 | 5.2 (main 4) | только main | Снижение ставки **ровно по консенсусу** («котировки не отреагировали, в ценах»): подкатегорию **5.2 модель взяла верно**, но main отнесла к ДЕЙСТВИЮ (4), а не к инфошуму (5). Самый трудный boundary-кейс. |

**Sonnet-5 на corner+sample (15 = 10 пограничных/спорных + 5 случайных): 14/15** — прогон-снимок
от 2026-07-12, не переигрывался. На тот момент Sonnet закрывал тонкую дизамбигуацию **4.x↔5.2**
(n36, n43), где нужен глубокий разбор. В прогоне 2026-07-23 Haiku **сам** классифицирует n36 и
подкатегорию n43 верно, поэтому выигрыш эскалации меньше, чем показывал снимок; n29 обе модели
дают 2.4 (та самая спорная метка). Стоимость Sonnet-подмножества: **$0.20** (вкл. thinking-токены).

**Вывод — «selective use» подтверждён данными.** Дешёвый Haiku (main 94% / sub 96%, ~$0.0036/шт)
насыщает рутинную классификацию; эскалация на Sonnet (~$0.013/шт) окупается на самых тонких
пограничных кейсах M+. Opus не гоняли — потолок уже достигнут, экономия бюджета.

## Контракт промптов L0 (офлайн-страж)

L0-конвейер держит инвариант: каждый ключ, который `orchestrator.fill_prompt()` подставляет,
обязан присутствовать как `<KEY>` в промпте агента (`<НОВОСТЬ>` / `<STATE_JSON>` /
`<RAG_ANALOGS>` / …), а блок `## Промпт` — извлекаться `extract_prompt` целиком (без обрыва
вложенным ```-fence; вложенные блоки — на `~~~`).

Закреплено офлайн regression-тестом [`tests/test_l0_prompt_contract.py`](../_tools/tests/test_l0_prompt_contract.py)
(без API, CI-safe). Схема gold-set — [`tests/test_l0_gold_set.py`](../_tools/tests/test_l0_gold_set.py).

---

## Честные оговорки

- **N=50, sanity-check.** Не заявляем статистической значимости.
- **In-sample по духу.** Gold-метки и таксономия писались одной командой; это проверка
  «промпт делает то, что задумано», а не независимый hold-out.
- **Синтетические новости.** Переформулированы из примеров таксономии; реальных
  клиентских данных нет.
- **Boundary-кейсы вынесены отдельно** — именно там живёт содержательная неоднозначность.
- **n29 — спорная метка**, а не ошибка модели; оставлена как есть и засчитана как промах
  (не подгоняем разметку под ответы моделей).

## Воспроизведение

```bash
cd _tools
export ANTHROPIC_API_KEY=...                     # без ключа — graceful exit, CI-safe
python eval_l0_classifier.py --model haiku        # N=50, ~$0.18
python eval_l0_classifier.py --model sonnet       # N=50, дороже (thinking)
python eval_l0_classifier.py --model haiku --gold data/l0_gold_set.json   # сокращённый набор N=15
```
